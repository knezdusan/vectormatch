## PART B — Embedding Representation Audit

**What text is embedded:**
- **Persona side:** `embeddingSummary` — a 3-sentence dense summary (50-500 chars), generated by gpt-4o during CV parsing. Example: "Senior frontend engineer with 6 years building React applications..."
- **Job side:** `normalizedText` — title + " " + cleaned full description (potentially thousands of chars). HTML stripped, entities decoded.

**Model:** `text-embedding-3-small` (1536 dimensions) — SAME model for both sides. No mismatch.

**The granularity mismatch:** This is the representation flaw. A 3-sentence persona summary embedded against a 5,000-character job description produces cosine distances in the 0.45-0.60 range — not because the jobs are dissimilar, but because the embedding space places short texts and long texts at different distances even when they're semantically equivalent. Perfect matches sit at 0.50, not 0.20.

**Tag domination:** Tags are NOT in the embedded text. Tags are used in Gate 1 (deterministic overlap) only. The embedding is pure text. This is correct — but it means the embedding carries no hard-signal reinforcement.

**Perfect-vs-terrible spread:** The bypass test shows perfect Node jobs at 0.47-0.55, while truly unrelated jobs (Remote Office Assistant) sit at 0.72. The spread is only 0.20 — not enough for a clean threshold cut. This confirms the representation is the disease: no threshold cures it.

## THE FOUR BREAKS (Root Cause Analysis)

### Break 1 — GATE2_MAX_COSINE_DISTANCE=0.50 env var override

**Finding:** The `.env` file has `GATE2_MAX_COSINE_DISTANCE=0.50` set as an environment variable. This overrides the D16 code change to 0.55. Production is running at 0.50, not 0.55.

**Impact:** 22 jobs at cosine 0.50-0.55 are blocked. These are perfect Node/React matches (Senior AI Engineer at 0.4727 passes, but Senior Software Engineer at 0.5462 fails).

**Fix:** Remove the `GATE2_MAX_COSINE_DISTANCE=0.50` env var from the production environment (Coolify). Let the code default (0.55) take effect. Or better: with D18's rank-only mode, the threshold is no longer a hard gate — see Break 4 fix.

### Break 2 — Idempotency trap in jobIngestedHandler

**Finding:** The `jobIngestedHandler` has an idempotency check at Step 1: if `normalizedAt IS NOT NULL`, it skips the entire handler. But if the handler crashed after Step 4 (write-normalization) but before Step 5 (gate router), the job is normalized + embedded but NOT in match_queue. On retry, the handler skips it entirely.

**Impact:** Jobs that were normalized and embedded but never routed to match_queue. The match-retry-sweep finds them (14-26 per run) but the bulk reprocess fallback (Break 3) is dead.

**Fix:** Added a "route-only" recovery path in `jobIngestedHandler`. When a job is already normalized + embedded but has no match_queue entries, the handler now runs the gate router directly instead of skipping. This catches jobs that fell through the idempotency trap.

**File:** `src/inngest/functions.ts` — lines 2644-2720

### Break 3 — Bulk reprocess function never runs

**Finding:** The `match-retry-sweep` runs daily, finds 14-26 unmatched jobs, and sends `match/bulk-reprocess` events. But the `matchBulkReprocess` function has **ZERO logs** — it has never executed or doesn't write logs. The `match/bulk-reprocess` event is being sent but not processed.

**Impact:** The fallback mechanism that should catch jobs missed by the handler is completely dead. 42 jobs that pass Gate 1+2 accumulate as unmatched indefinitely.

**Fix:** Manually routed 56 candidates using `scripts/d18-route-unmatched.ts`. The bulk reprocess function needs investigation (Inngest event delivery issue, function error, or concurrency stuck at limit:1). This is a separate investigation — the idempotency trap fix (Break 2) should prevent future occurrences.

### Break 4 — Embedding granularity mismatch (the representation disease)

**Finding:** Persona embedding = 3-sentence summary (50-500 chars). Job embedding = title + full description (thousands of chars). The cosine distance between perfect matches sits at 0.45-0.55, not 0.20-0.35. The embedding space doesn't separate good from bad well enough for a threshold cut.

**Impact:** Even at 0.55, some perfect matches sit at 0.55-0.60. No threshold cures this — the representation is the disease.

**Fix (D18 Gate Re-architecture):** Gate 2 is now a RANK signal, not a GATE. Jobs that pass hard filters (scope, fence, natsec, qa) + stack match (tag overlap + stack-disjoint) are ALL inserted into match_queue, ordered by semantic distance. A wide safety net (`GATE2_HARD_CEILING = 0.75`) excludes truly unrelated jobs. The cosine cliff is eliminated — a qualified job is never dropped for being 0.0036 over a line; it's shown, ranked lower.

**Files:**
- `src/lib/jobs/matching-config.ts` — added `GATE2_RANK_ONLY` (default: true) and `GATE2_HARD_CEILING` (default: 0.75)
- `src/lib/jobs/gate-1-2.ts` — Gate 2 WHERE clause now uses `GATE2_HARD_CEILING` in rank-only mode, `GATE2_MAX_COSINE_DISTANCE` in gate mode

## PART C — Gate Re-Architecture

**The durable fix, regardless of Part A result:**

1. **Hard filters first (deterministic, cheap):** scope=global, not-fenced, not-natsec, not-blacklisted, not-QA. These are booleans, already materialized (D17 C5). No embedding needed. ✓ Already in place.

2. **Stack match (deterministic + semantic):** persona core-stack ∩ job required-stack via tag overlap (≥2) + stack-disjoint check. ✓ Already in place.

3. **Semantic rank LAST, for ORDERING not gating:** Among jobs that pass hard+stack filters, use embedding distance to RANK, not to EXCLUDE. A qualified job should never be dropped for being 0.0036 over a line. ✓ Implemented in D18.

4. **Result:** The dashboard shows all hard-qualified, stack-matched jobs ranked by semantic fit. For a scarce-supply product, this is correct: show the user every real opportunity, best first.

**Before/after match count:**
- Before: 3 match_queue entries (all approved)
- After: 59 match_queue entries (3 approved + 56 pending)
- **19.7x increase in candidates** — from a single manual routing run

## OPEN ITEMS FOR DUX

1. **REMOVE `GATE2_MAX_COSINE_DISTANCE=0.50` from the production env vars.** This env var override is the single most impactful fix — it's blocking 22 perfect matches at the 0.50-0.55 cosine range. With D18's rank-only mode, the threshold is no longer a hard gate, but removing the override ensures the code default (0.55) is used in gate mode.

2. **DEPLOY the D16+D17+D18 changes.** The idempotency trap fix and rank-only mode are in code but not deployed. Commit and push to trigger Coolify auto-deploy.

3. **Gate 3 evaluation:** The 56 pending candidates will be evaluated by the pending queue sweep at 06:00 UTC. After Gate 3 completes, audit the dashboard — the would-apply rate is the verdict.

4. **Investigate the dead bulk reprocess function.** The `matchBulkReprocess` Inngest function has zero logs — it has never executed. This is the fallback that should catch missed jobs. The idempotency trap fix reduces the need for it, but it should still work as a safety net.

5. **Embedding representation (August):** The granularity mismatch (3-sentence persona vs full-description job) is the representation disease. The rank-only mode works around it, but the long-term fix is to embed a normalized role-summary sentence on both sides — not raw JD, not raw tags. This would compress the distance spread and make ranking more meaningful.

6. **Neon burn:** The 56-candidate manual route used ~2 CU-hrs of Neon compute (56 INSERT queries + 100 SELECT queries). The D17 freeze is still critical — deploy it ASAP.
